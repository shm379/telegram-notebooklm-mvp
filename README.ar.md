# Telegram NotebookLM MVP

**Languages / زبان‌ها:** [English](README.md) · [فارسی](README.fa.md) · [العربية](README.ar.md) · [Español](README.es.md) · [简体中文](README.zh.md)

هذا منتج بحد أدنى من الميزات (MVP) لبناء **أرشيف Telegram ذكي**؛ مشروع يمكنه جمع محتوى القنوات والمحادثات والملفات ومقاطع الفيديو والرسائل المُعاد توجيهها، وتحويلها إلى نص قابل للبحث، وفي النهاية الإجابة عن أسئلة المستخدم مثل **NotebookLM داخلي لـ Telegram**.

الهدف النهائي للمشروع هو تمكين المستخدم من تحويل محتوى Telegram الخاص به إلى ذاكرة قابلة للبحث يمكن ربطها بأدوات الذكاء الاصطناعي؛ من داخل بوت Telegram، ولوحة التحكم على الويب، ومستقبلاً عبر MCP للربط بأدوات مثل ChatGPT وClaude وCursor والوكلاء الشبيهين بـ Codex وغيرها من عملاء الذكاء الاصطناعي.

---

## الفكرة الأساسية

يستهدف هذا المشروع ثلاثة أوضاع رئيسية:

### 1. استيراد قناة / محادثة

يقدّم المستخدم رابط أو معرّف قناة عامة أو محادثة لديه صلاحية الوصول إليها، ويسترجع النظام رسائلها وتسمياتها التوضيحية ووسائطها.

مثال:

```text
/ingest https://t.me/example_channel
```

### 2. صندوق الوارد للرسائل المُعاد توجيهها

يمكن للمستخدم إعادة توجيه رسالة أو منشور أو ملف أو صورة أو فيديو أو PDF أو أي محتوى إلى البوت. ويقوم النظام بتخزينه ومعالجته ووسمه وجعله قابلاً للبحث.

يُقصد بهذا الجزء أن يعمل مثل **صندوق وارد ذكي لـ Telegram**.

### 3. دفتر ملاحظات بالذكاء الاصطناعي / RAG

بعد تخزين المحتوى وفهرسته، يمكن للمستخدم طرح أسئلة على أرشيفه:

```text
/ask از بین پیام‌هایی که درباره Al Mouj ذخیره کردم، کدام‌ها درباره townhouse بودند؟
```

أو:

```text
/ask ابزارهای AI که در کانال‌ها درباره ساخت ویدیو معرفی شده‌اند را دسته‌بندی کن
```

يجب أن تأتي الإجابة مرفقة بالمصدر، ورابط الرسالة، والنصوص المرتبطة.

## حالة الـ MVP الحالية

في النسخة الحالية، يمتلك المشروع هذه القدرات:

- استقبال رابط قناة Telegram وقراءة الرسائل باستخدام `Telethon`
- تنزيل ومعالجة الرسائل النصية والصوتية والمرئية
- استخراج الصوت من الفيديو باستخدام `ffmpeg`
- تفريغ الصوت/الفيديو إلى نص باستخدام OpenAI أو Gemini
- تقسيم النصوص إلى مقاطع
- بناء التضمينات (embeddings) للبحث الدلالي
- بحث بالكلمات المفتاحية + بحث دلالي
- توليد إجابات أولي قائم على RAG من نتائج البحث
- لوحة تحكم ويب خفيفة باستخدام `Python http.server`
- بوت Telegram للتنسيق والأوامر الأساسية
- ربط حساب Telegram الحقيقي للمستخدم عبر سلسلة جلسة (session string) من خلال Telethon
- **صندوق الوارد للرسائل المُعاد توجيهها**: إعادة توجيه أي رسالة إلى البوت تخزّن نصها/تسميتها التوضيحية في صندوق الوارد الشخصي القابل للبحث الخاص بالمستخدم
- **معالجة الوسائط المُعاد توجيهها**: تُفرّغ ملفات الصوت/الفيديو/الرسائل الصوتية تلقائياً، وتُحوَّل الصور وملفات PDF إلى نص قابل للبحث عبر التعرف الضوئي على الحروف (OCR) بواسطة Gemini. كما تُستخرَج ملفات DOCX/XLSX محلياً (دون مفتاح API ودون اتصال بالشبكة)
- **محرّك القواعد + الوسوم**: تعريف قواعد بصيغة كلمة مفتاحية←وسم، الوسم التلقائي للمحتوى الوارد، وتصفية `/search` و`/ask` باستخدام `--tag`
- **قواعد الذكاء الاصطناعي**: `/rule add-ai` مع معيار بلغة طبيعية (يُطابَق بواسطة نموذج لغوي كبير LLM)، و`/airules` للوسم التلقائي الاختياري على الرسائل المُعاد توجيهها الجديدة
- **إدارة الوسوم والتصفّح**: `/tag rename|delete`، و`/recent` لأحدث العناصر، ونقاط النهاية على الويب `/api/{stats,recent,timeline}` + لوحة مكتبة في لوحة التحكم
- **الإعادة التلقائية للتوجيه إلى قناة أرشيف**: باستخدام `/setarchive`، أي رسالة تعيد توجيهها وتطابق قاعدة وسم تُعاد توجيهها تلقائياً أيضاً إلى قناة الأرشيف الخاصة بك
- **مهام الاستيراد**: استيراد كامل للقناة في الخلفية مع طابور انتظار، وتتبع التقدّم، والاستئناف بعد الانقطاع، وإمكانية الإلغاء
- **التلخيص (NotebookLM)**: `/summarize` لبناء ملخص منظَّم للأرشيف بأكمله، أو مصدر محدد، أو وسم
- **الخلاصة (Digest)**: `/digest [days]` يبني ملخصاً بالذكاء الاصطناعي للمحتوى الحديث (7 أيام افتراضياً)
- **تجميع المواضيع**: `/topics` يجمّع محتوى الأرشيف حسب الموضوع دون اتصال بالشبكة (اعتماداً على التضمينات الموجودة)؛ وإذا توفّر مفتاح Gemini، يُبنى تصنيف كل عنقود بواسطة نموذج لغوي كبير (وإلا فمن أكثر المصطلحات تكراراً)
- **الخط الزمني**: `/timeline` يجمّع الأرشيف حسب التاريخ (شهر أو يوم) — وهو المكمّل الزمني لـ `/topics`
- **التصدير**: `/export` يصدّر الأرشيف بأكمله، أو مصدراً واحداً، أو وسماً واحداً، كملف Markdown قابل للتنزيل
- **الإحصائيات**: `/stats` يعرض نظرة عامة على الأرشيف (عدد العناصر والمصادر والوسوم، وأنواع الوسائط، والمدى الزمني)
- **المجموعات (دفاتر الملاحظات)**: `/collection` يجمّع عدة وسوم تحت اسم واحد ويعرض عناصر المجموعة
- **استيراد نسخة Telegram الاحتياطية**: يأخذ ملف *JSON القابل للقراءة آلياً* من Telegram Desktop (`result.json` أو ملف `.zip` لمجلد التصدير) — سواء تصدير محادثة واحدة أو الحساب بالكامل — يجعل كل الرسائل قابلة للبحث، ويعيد نسخة **Markdown**. في البوت، أرسل الملف فحسب؛ على الويب، حمّله من بطاقة "Import Telegram Backup".
- **موقع تعريفي + تطبيق ويب**: صفحة تعريفية على `/` ولوحة تحكم كاملة (Ingest / Search / Ask / Library / Backup import) على `/app`
- **خادم MCP (للقراءة فقط)**: يكشف الأرشيف لأدوات الذكاء الاصطناعي عبر JSON-RPC على stdio (`python -m telegram_notebook.mcp_server`)

## لماذا لا تكفي Bot API؟

لالتقاط أرشيف كامل لقناة أو محادثة، لا تكفي Bot API وحدها. فعادةً ما ترى Bot API الرسائل الجديدة فقط التي يملك البوت صلاحية الوصول إليها.

لاستيراد سجلّ القنوات والمحادثات، يستخدم هذا المشروع `Telethon` و MTProto؛ أي بنفس مستوى وصول حساب المستخدم، وليس مجرد رمز بوت.

## البنية الحالية

```text
بوت Telegram
  |
  | أوامر المستخدم: /connect, /ingest, /search, /ask
  v
الخلفية البرمجية بلغة Python
  |
  +-- عميل Telethon
  |     قراءة القنوات والمحادثات
  |
  +-- خط معالجة الاستيعاب (Ingestion Pipeline)
  |     تنزيل الوسائط، استخراج النص، التفريغ النصي
  |
  +-- التقسيم + التضمين (Chunking + Embedding)
  |     التحضير للبحث الدلالي
  |
  +-- خدمة البحث (Search Service)
  |     بحث بالكلمات المفتاحية + بحث متّجهي
  |
  +-- مولّد إجابات RAG
        بناء الإجابة من المصادر المُكتشَفة
```

## أوامر البوت

```text
/start
تعريف بالمشروع والبدء في الاستخدام

/connect
ربط حساب Telegram الحقيقي للمستخدم

/status
التحقق من حالة الاتصال

/ingest <channel_url>
فهرسة سريعة ومباشرة لقناة

/import <channel_url> [limit]
وضع استيراد كامل قابل للاستئناف في طابور الانتظار في الخلفية

/backup
دليل لاستيراد ملف نسخة Telegram الاحتياطية؛ ما عليك سوى إرسال ملف result.json أو .zip إلى البوت

/jobs
عرض حالة مهام الاستيراد وتقدّمها

/canceljob <id>
إلغاء مهمة في طابور الانتظار أو قيد التشغيل

/search <query>
البحث في الأرشيف

/search <query> --source <channel_url>
البحث ضمن مصدر محدد فقط

/search <query> --tag <tag>
البحث ضمن المحتوى الموسوم فقط

/ask <question>
طرح سؤال على الأرشيف بالذكاء الاصطناعي

/ask <question> --source <channel_url>
طرح السؤال من قناة أو مصدر محدد فقط

/ask <question> --tag <tag>
طرح السؤال من محتوى وسم محدد فقط

/summarize [--source <url>] [--tag <tag>]
تلخيص الأرشيف بأكمله، أو مصدر، أو وسم

/digest [days]
ملخص بالذكاء الاصطناعي للمحتوى الحديث (7 أيام افتراضياً)

/topics [--source <url>] [--tag <tag>]
تجميع المحتوى حسب المواضيع

/timeline [--source <url>] [--tag <tag>] [--day]
عرض زمني للأرشيف حسب الشهر (أو اليوم باستخدام --day)

/export [--source <url>] [--tag <tag>]
تنزيل تصدير Markdown للأرشيف بأكمله، أو مصدر، أو وسم

/recent [n]
عرض أحدث n عنصر (10 افتراضياً)

/stats
نظرة عامة على الأرشيف (عدد العناصر والمصادر والوسوم، أنواع الوسائط، المدى الزمني)

/sources
عرض المصادر المفهرسة

/delete <channel_url>
حذف بيانات مصدر

/rule add <keyword> -> <tag>
تعريف قاعدة كلمة مفتاحية لوسم المحتوى تلقائياً

/rule add-ai <criterion> -> <tag>
تعريف قاعدة ذكاء اصطناعي (تُطابَق بواسطة نموذج لغوي كبير، أثناء /rule apply)

/rule list
عرض القواعد

/rule remove <id>
إزالة قاعدة

/rule apply
إعادة تطبيق القواعد على المحتوى الموجود (تعبئة رجعية)

/airules on|off
تشغيل قواعد الذكاء الاصطناعي تلقائياً على كل رسالة مُعاد توجيهها جديدة (اختياري؛ معطّل افتراضياً)

/tags
عرض الوسوم وعدد العناصر لكل وسم

/tag rename <old> -> <new>
إعادة تسمية وسم (أو دمجه في وسم موجود)

/tag delete <tag>
حذف وسم من جميع العناصر

/collection new|add|list|remove|show <name>
تجميع عدة وسوم تحت "دفتر ملاحظات" وعرض عناصره
(يمكنك بعد ذلك تلخيص/تصدير دفتر الملاحظات بأكمله باستخدام /summarize --collection <name> أو /export --collection <name>)

/setarchive <@channel | off>
تعيين قناة الأرشيف؛ تُرسَل الرسائل المُعاد توجيهها الموسومة إليها تلقائياً

/cancel
إلغاء العملية الحالية
```

## واجهات برمجة التطبيقات الأساسية

### استيعاب قناة (Ingest Channel)

```bash
curl -X POST http://127.0.0.1:8000/api/channels/ingest \
  -H 'content-type: application/json' \
  -d '{
    "channel_url": "https://t.me/example_channel",
    "limit": 50
  }'
```

### البحث (Search)

```bash
curl -X POST http://127.0.0.1:8000/api/search \
  -H 'content-type: application/json' \
  -d '{
    "query": "هوش مصنوعی و تولید ویدیو",
    "channel_url": "https://t.me/example_channel",
    "top_k": 5
  }'
```

### السؤال بالذكاء الاصطناعي (Ask AI)

```bash
curl -X POST http://127.0.0.1:8000/api/ask \
  -H 'content-type: application/json' \
  -d '{
    "query": "از این کانال چه ابزارهایی برای ساخت ویدیو معرفی شده؟",
    "channel_url": "https://t.me/example_channel"
  }'
```

### الإحصائيات / الأحدث / الخط الزمني (للقراءة فقط)

```bash
curl http://127.0.0.1:8000/api/stats
curl 'http://127.0.0.1:8000/api/recent?limit=10'
curl 'http://127.0.0.1:8000/api/timeline?granularity=month'
```

هذه النقاط، مثل بقية الـ API، محمية بـ `WEB_API_TOKEN` (أو الوصول المحلي loopback فقط عند عدم تعيين رمز).

## وجهة المنتج النهائية

الهدف النهائي لهذا المشروع ليس مجرد بحث بسيط. وجهة المنتج هي كما يلي:

```text
أرشيف Telegram بالذكاء الاصطناعي
  |
  +-- استيراد كامل للقنوات والمحادثات
  +-- صندوق وارد للرسائل المُعاد توجيهها
  +-- محرّك قواعد لفصل المحتوى بالكلمة المفتاحية أو الذكاء الاصطناعي
  +-- وسم / مجلد / مجموعة
  +-- بحث معجمي ودلالي
  +-- NotebookLM داخلي للأسئلة والأجوبة
  +-- خادم MCP للربط بأدوات الذكاء الاصطناعي
```

## محرّك القواعد + الوسوم

يمكن للمستخدم تعريف قواعد بصيغة كلمة مفتاحية←وسم:

```text
/rule add Claude -> AI Tools
/rule add Al Mouj -> Real Estate
/rule add golden visa -> Oman Visa
/rule add قیمت -> Leads
```

أي محتوى جديد يدخل النظام (استيعاب قناة، تفريغ وسائط، أو صندوق الوارد للرسائل المُعاد توجيهها) يُفحَص نصه وتسميته التوضيحية. إذا كانت الكلمة المفتاحية لإحدى القواعد (كنص فرعي وغير حساس لحالة الأحرف) موجودة في النص:

- يُرفَق الوسم المقابل بذلك العنصر
- يمكن لاحقاً تصفيته باستخدام `/search ... --tag <tag>` و`/ask ... --tag <tag>`
- يعرض `/tags` الوسوم وعدد العناصر لكل وسم
- يعيد `/tag rename <old> -> <new>` تسمية وسم (أو يدمجه في وسم موجود)، ويزيل `/tag delete <tag>` وسماً من جميع العناصر
- يعيد `/rule apply` تطبيق القواعد الحالية على المحتوى الموجود (تعبئة رجعية)

**القواعد القائمة على الذكاء الاصطناعي:** بالإضافة إلى قواعد الكلمات المفتاحية، يمكنك تعريف قاعدة بمعيار بلغة طبيعية يقرر مطابقته نموذج لغوي كبير:

```text
/rule add-ai پست‌هایی که درباره‌ی ابزارهای ساخت ویدیو با هوش مصنوعی هستند -> Video AI
/rule add-ai هر چیزی مرتبط با قیمت و فروش ملک -> Leads
```

بسبب تكلفة النموذج اللغوي الكبير، تُشغَّل قواعد الذكاء الاصطناعي فقط أثناء `/rule apply` (استدعاء واحد للنموذج اللغوي لكل عنصر) وتتطلب مفتاح Gemini؛ وإذا لم يُعيَّن مفتاح، يتم تجاهلها ويُبلَّغ عن ذلك في المخرجات. وما تزال قواعد الكلمات المفتاحية تُطبَّق تلقائياً عند كل استيعاب.

**الإعادة التلقائية للتوجيه:** باستخدام `/setarchive <@channel>` تُعيَّن قناة أرشيف؛ ومن ثَمَّ أي رسالة تعيد توجيهها إلى البوت ويطابق نصها قاعدة وسم تُعاد توجيهها — بالإضافة إلى تخزينها في صندوق الوارد — إلى تلك القناة أيضاً مع مصدرها/وسومها/رابطها (يجب أن يكون البوت مشرفاً على القناة). للتعطيل: `/setarchive off`.

بالإضافة إلى `/rule apply`، تُشغَّل قواعد الذكاء الاصطناعي أيضاً تلقائياً على كل رسالة مُعاد توجيهها جديدة باستخدام `/airules on` (اختياري، استدعاء واحد للنموذج اللغوي لكل عنصر؛ ولا تُصنَّف عمليات استيراد القنوات المجمّعة تلقائياً أبداً).

**لم يُضَف بعد (متابعة لاحقة):** الإعادة التلقائية للتوجيه لعمليات استيراد القنوات (في الوقت الحالي، مسار صندوق الوارد للرسائل المُعاد توجيهها فقط)، وتنزيل/معالجة الوسائط ضمن الاستيراد الكامل للقناة.

## استيراد نسخة Telegram الاحتياطية (JSON / ZIP)

يمكنك استيراد السجلّ الكامل لمحادثة أو حساب دون الحاجة إلى `/connect`:

1. في **Telegram Desktop**، اذهب إلى `Settings → Advanced → Export Telegram data` (أو، على محادثة: `Export chat history`).
2. اضبط الصيغة على **Machine-readable JSON** (وليس HTML).
3. المخرجات هي ملف `result.json` (أو مجلد يحتويه إلى جانب الوسائط)؛ يمكنك ضغط المجلد كـ zip.

ثم:

- **من البوت:** أرسل ملف `result.json` أو `.zip` مباشرة إلى البوت. يستورده البوت، ويجعل المحتوى قابلاً للبحث، ويعيد نسخة Markdown. (حدّ 20 ميغابايت بسبب حد التنزيل في Bot API؛ لملف أكبر، استخدم الويب.)
- **من الويب:** في `/app`، في بطاقة "Import Telegram Backup"، حمّل الملف. يصبح المحتوى قابلاً للبحث في أرشيف الويب ويظهر زر تنزيل Markdown.

تصبح كل محادثة مصدراً اصطناعياً `backup://<id>` ويكون الاستيراد متماثلاً (إعادة استيراد الملف نفسه لا تضيف شيئاً).

### API

```bash
curl -X POST 'http://127.0.0.1:8000/api/backup/import' \
  -H 'X-Filename: result.json' \
  -H 'content-type: application/octet-stream' \
  --data-binary @result.json
```

تتضمن الاستجابة عدد المحادثات/الرسائل المستوردة ونص Markdown الكامل. ومثل بقية الـ API، فهي محمية بـ `WEB_API_TOKEN` (أو الوصول المحلي loopback).

## خادم MCP

تم تنفيذ **خادم MCP لـ Telegram** (للقراءة فقط) كي لا يبقى أرشيف Telegram الخاص بالمستخدم محصوراً في البوت ويمكن ربطه بأدوات ذكاء اصطناعي أخرى (Claude وCursor و…). يعمل عبر JSON-RPC 2.0 على stdio وهو مكتوب باستخدام المكتبة القياسية فقط (دون تبعيات جديدة).

التشغيل:

```bash
MCP_OWNER_ID=0 python -m telegram_notebook.mcp_server
```

يحدّد `MCP_OWNER_ID` أرشيف أي مستخدم يُكشَف (الافتراضي `0` = أرشيف لوحة التحكم على الويب؛ ولأرشيف مستخدم بوت، قدّم `bot_user_id` الخاص به).

أدوات MCP الحالية:

```text
list_sources              عرض القنوات/المحادثات وصندوق الوارد للرسائل المُعاد توجيهها
list_tags                 عرض الوسوم وعدد العناصر لكل وسم
search_telegram_archive   البحث (مع مرشّح اختياري للمصدر/الوسم)
get_message               النص الكامل لعنصر حسب media_item_id
ask_telegram_notebook     أسئلة وأجوبة RAG على الأرشيف
summarize_source          تلخيص الأرشيف بأكمله، أو مصدر، أو وسم
list_topics               تجميع المحتوى حسب المواضيع (دون اتصال، من التضمينات)
timeline                  عدّ العناصر حسب الفترة الزمنية (شهر/يوم)
archive_stats             نظرة عامة على الأرشيف (الأعداد، أنواع الوسائط، المدى الزمني)
list_recent               قائمة بأحدث عناصر الأرشيف (الأحدث أولاً)
```

جميع الأدوات للقراءة فقط؛ الأدوات الحساسة (import وforward وdelete وcreate_rule) غير مكشوفة عمداً، وإذا لزم الأمر يجب إضافتها لاحقاً مع صلاحية وتأكيد.

## القيود الحالية

- عزل البيانات بين المستخدمين قائم (يرى كل مستخدم بياناته فقط؛ تُفرَض الملكية عبر `owner_id` على القنوات).
- أُضيف توثيق Web API باستخدام `WEB_API_TOKEN` وتشفير الأسرار في قاعدة البيانات باستخدام `SECRETS_KEY`؛ عيّن المتغيرين كليهما للإنتاج.
- التخزين الحالي مناسب للـ MVP، وليس لمجموعة بيانات كبيرة.
- يجب تشفير سلسلة الجلسة ومفاتيح API قبل الإنتاج.
- الاستيراد الكامل للقناة مع طابور انتظار وتقدّم واستئناف مدعوم عبر `/import` (عامل في الخلفية)؛ ولا توجد بعد بيئة اختبار معزولة لمسار Telethon بأكمله.
- بالإضافة إلى النص/التسمية التوضيحية، يعالج صندوق الوارد للرسائل المُعاد توجيهها الوسائط المُعاد توجيهها: الصوت/الفيديو/الرسالة الصوتية عبر التفريغ، والصور/PDF عبر OCR (Gemini متعدد الوسائط)، وDOCX/XLSX عبر الاستخراج المحلي (zipfile + XML، دون مفتاح API) تُحوَّل إلى نص. ولم يُضَف بعد تنزيل الوسائط ضمن الاستيراد الكامل للقناة.
- يعتمد محرّك القواعد على مطابقة الكلمات المفتاحية (نص فرعي)؛ ولم تُضَف بعد القواعد القائمة على الذكاء الاصطناعي والإعادة التلقائية للتوجيه إلى قناة أرشيف.
- يؤدي `/topics` تجميع المواضيع على التضمينات الموجودة (جشِع باستخدام جيب التمام، دون اتصال)؛ ويتطلب أن يكون المحتوى مفهرساً بمفتاح تضمين. وتُبنى تصنيفات العناقيد بنموذج لغوي كبير إذا توفّر مفتاح Gemini، وإلا يعود إلى أكثر المصطلحات تكراراً. ويبني `/timeline` عرضاً زمنياً (شهر/يوم) على تواريخ الرسائل.
- لمجموعة بيانات كبيرة، يُفضّل الانتقال إلى PostgreSQL + pgvector أو Qdrant.
